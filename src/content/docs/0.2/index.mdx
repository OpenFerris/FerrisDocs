Ferris convierte una descripción de datos en una aplicación completa. Los
**DocTypes** declaran campos, permisos y ciclo de vida; el motor aplica
validación, naming, workflows y auditoría; el **Desk** genera formularios,
listas, dashboards y widgets a partir de esa misma descripción. Las
funcionalidades externas se publican como **apps WASM** que el host carga en su
propio sandbox.

No hay que escribir HTML ni JavaScript para el CRUD: se declara el DocType y el
resto se deriva. Y una app externa no tiene que estar escrita en Rust — el
contrato es WIT y acepta Python, JavaScript/TypeScript, Go, C/C++/C#, Zig o
cualquier toolchain que produzca un componente del world `ferris-app`.

## El framework en una vista

Un DocType es una declaración; el motor y el Desk hacen el resto. Este ejemplo
es del portal **Ferris**; si vas a escribir una app WASM, empieza en
[Apps](/0.2/apps/) y elige tu lenguaje.

```rust
use ferris_schema::{DoctypeMeta, FieldMeta, RolePermission};

pub fn invoice_meta() -> DoctypeMeta {
    DoctypeMeta::new("Invoice", "Billing")
        .description("Una factura emitida a un cliente.")
        .title_field("customer")
        .naming_series("INV-.#####")
        .submittable()
        .field(FieldMeta::link("customer", "Customer").required().in_list_view())
        .field(FieldMeta::currency("total").label("Total"))
        .field(FieldMeta::select("status", "Draft\nPaid\nVoid"))
        .permission(RolePermission::new("Billing User").read().write().create())
        .permission(RolePermission::new("Billing Manager").read().write().create().submit())
}
```

```bash
ferris new billing --into plugins/billing
ferris migrate
ferris serve --all
```

## Una app, cualquier lenguaje

Una app es un componente WebAssembly que implementa el world `ferris-app`:
declara lo que ofrece en `describe()` y el host monta sus DocTypes, rutas,
widgets y hooks. El componente puede venir de cualquiera de estas cadenas:

<CardGrid>
  <Card title="Rust" icon="rocket">
    `wit-bindgen` y `cargo build --target wasm32-wasip2`.
    [Guía →](/0.2/apps/languages/rust/)
  </Card>

  <Card title="Python" icon="document">
    `componentize-py` envuelve el intérprete en el componente.
    [Guía →](/0.2/apps/languages/python/)
  </Card>

  <Card title="JavaScript / TypeScript" icon="window">
    `jco` genera el proyecto y compila a componente.
    [Guía →](/0.2/apps/languages/javascript/)
  </Card>

  <Card title="Go" icon="server">
    `componentize-go` produce el `.wasm` desde un módulo Go.
    [Guía →](/0.2/apps/languages/go/)
  </Card>
</CardGrid>

## Política de versiones

La versión de Cargo y la del contrato WIT son **la misma cifra**, y esa cifra
indica compatibilidad: un patch no toca el contrato, una minor añade superficie
retrocompatible y una major rompe. Ferris está en `0.2.0`, así que todavía es
pre-1.0; fija un tag o un commit para producción.

[Leer la política completa →](/0.2/referencia/versionado/)
